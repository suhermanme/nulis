Your own theme colors: duplicate any theme, edit its colors, and keep it.

## Themes

- **Your own theme colors.** In **Settings ▸ Appearance & Themes**, press **Duplicate Selected** on any theme — a built-in, one you installed, or a copy of your own — and the panel opens an editable copy of it, marked **· User** in the list. Each color has a native color picker, a hexadecimal field, and arrow-key nudges; the name is a field you type over, and the copy keeps its own id, so shortcuts and settings that point at a theme keep pointing at it.
- **The store button names what it writes:** **Save Copy** for a new copy, then **Save Colors**, **Save Name**, or **Save Name & Colors** after edits. **Revert** throws an unsaved draft away. Nothing reaches the editor until you press **Apply**.
- **A live preview in the panel** paints the copy's colors as you pick them — the same colors the editor will paint — so you see the theme before you save it.
- **Remove Selected** uninstalls a theme you installed. It asks first, it cannot remove a built-in, and it refuses the theme Nulis is using until you switch to another. Built-in themes and installed theme files are read-only; every write goes to a copy you made.
- **The theme you apply paints the editor and every Nulis window** — the side panels, the status line, the title bar mark, the About background — and comes back the same after a restart. A built-in theme paints its own colors, so its chrome never shifts. The Appearance panel has no second control for this; the **Apply theme colors** checkbox from the preview builds is gone, and applying a theme applies it everywhere.

## Readability

- **The panel says when Nulis will paint a stronger color.** Four colors — the **text selection**, **secondary text**, **toolbar icons**, and **disabled icons** — are measured against contrast floors, so you can always see them. Pick a color below a floor and the theme file keeps your color exactly, while the row tells you what will be painted: **"Nulis paints #43586B — Editor Selection stays readable. Your color is saved as typed."** Every other color paints exactly as you typed it. Help has the same text under **Settings and Themes ▸ Theme colors and readability**.
- **To get a highlight that paints as typed,** give the text on it room: darken **`editor.foreground`**, or pick a darker highlight, so the two clear 4.5:1.

## Changed

- Applying a theme now always recolors every Nulis window. In earlier builds the editor recolored and the window chrome stayed behind unless the **Apply theme colors** checkbox was ticked, which confused the two.
- A color that the readability floors strengthen now says so in the panel. Previously it saved, and painted a color you did not pick, with nothing naming why.
- A theme document written by an older build, with the **Apply theme colors** setting, loads unchanged; the setting decides nothing now and is dropped from the stored preferences.

## First launch

These builds are not signed with a paid Apple or Microsoft certificate, so each system asks once.

- **macOS:** open the `.dmg` and drag Nulis into Applications, then open it. When macOS says it could not verify Nulis, click **Done**. Open **System Settings ▸ Privacy & Security**, scroll to **Security**, and click **Open Anyway** next to the message about Nulis; confirm with your password or Touch ID. You do this once per installed version.
- **Windows:** if SmartScreen shows *Windows protected your PC*, click **More info**, then **Run anyway**.
- **Linux:** no extra step; the package manager installs the libraries Nulis needs.

## Known limitations

- **Theme authoring is checked on macOS, partly.** Applying a theme, editing colors, and the readability notice were checked by hand on a local macOS build on 2026-10-25. Relaunch and restore, **Remove Selected**, and the window chrome in Windows and Linux are still to be checked by hand. Automated tests cover the save path, the built-in refusals, and the floors.
- **Themes you install, and your copies, are capped** at 64 files, and a theme file at 256 KiB. A theme is declarative data — colors, a name, the theme kind — and cannot contain CSS, scripts, URLs, imports, or remote resources.
- **Two settings windows editing the same copy** have last-write-wins semantics, like the rest of settings.
- **The floors apply to four colors only.** A pick outside them paints exactly as typed, so the strengthening is visible in some rows and absent in others.
- Builds are not signed with a Developer ID or code-signing certificate, hence the first-launch steps above.
- On Windows and Linux, Nulis does not yet add itself to the system's "Open with" list.
- Linux packages are for 64-bit x86 only.
