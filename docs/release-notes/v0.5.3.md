The Markdown preview no longer contacts web servers on its own.

## Markdown preview

- **Images from the web wait until you ask.** Fetching an image a Markdown file links from a web server, such as `![chart](https://example.com/chart.png)`, tells that server your address and when you opened the file, which is how tracking pixels work. The preview now shows a placeholder that names the server, with a **Load remote images** button. Pressing it loads every web image of that document, in every pane that shows it, until the document is closed. Images stored beside the file show as before.
- **Choose how web images behave** under **Settings ▸ Editor ▸ Markdown preview ▸ Remote images**: **Ask for each document** (the default), **Never load**, or **Always load**. In `settings.json` it is `"markdown": { "preview": { "remoteImages": "ask" } }`.
- **Plain `http://` images are never loaded,** whatever the setting, because the request and the image would travel unencrypted.
- **Print and Page Setup follow the preview:** a printed Markdown preview shows web images only when the preview on screen shows them.

## Fixed

- A web image that could not be loaded after **Load remote images** left an empty gap. It now says the image could not be loaded from its server.

## For contributors and packagers

- Building Nulis needs **Rust 1.90** or later. The previous "1.82" was out of date; Nulis's dependencies already needed 1.90. CI now builds with exactly the version `Cargo.toml` names, so the stated minimum and the tested one cannot drift apart again.
- The interface builds with **Node.js 24**, which `.nvmrc` names.
- [CONTRIBUTING.md](https://github.com/suhermanme/nulis/blob/main/CONTRIBUTING.md) explains how to contribute. Every commit is signed off under the Developer Certificate of Origin, and a CI check enforces it on pull requests. Bug and feature reports use issue forms.
- **Security problems** can be reported privately through GitHub's **Report a vulnerability** form; see [SECURITY.md](https://github.com/suhermanme/nulis/blob/main/docs/SECURITY.md#reporting-a-vulnerability).
- Installation help moved to [docs/INSTALL.md](https://github.com/suhermanme/nulis/blob/main/docs/INSTALL.md), and the README is shorter.
- The largest source files of the core and the interface are split by topic. Nothing a user sees changed.

## First launch

These builds are not signed with a paid Apple or Microsoft certificate, so each system asks once.

- **macOS:** open the `.dmg` and drag Nulis into Applications, then open it. When macOS says it could not verify Nulis, click **Done**. Open **System Settings ▸ Privacy & Security**, scroll to **Security**, and click **Open Anyway** next to the message about Nulis; confirm with your password or Touch ID. You do this once per installed version.
- **Windows:** if SmartScreen shows *Windows protected your PC*, click **More info**, then **Run anyway**.
- **Linux:** no extra step; the package manager installs the libraries Nulis needs.

## Known limitations

- **The remote-image change is checked on macOS only.** Windows and Linux have automated checks only.
- **Inline `data:` images** in Markdown are not shown in the preview (their alt text is). This was already the case before this release.
- **Export to PDF writes the Markdown source,** in Edit and View mode alike. To get a PDF of the formatted preview, use **Print…** in View mode and save as PDF from the system print dialog (**PDF ▸ Save as PDF** on macOS, **Microsoft Print to PDF** on Windows).
- Builds are not signed with a Developer ID or code-signing certificate, hence the first-launch steps above.
- On Windows and Linux, Nulis does not yet add itself to the system's "Open with" list.
- Linux packages are for 64-bit x86 only.
