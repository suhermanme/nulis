A terminal you can size and read, and a toolbar that names its controls.

## Terminal

- **Drag the divider to resize the terminal.** The bar between the editor and the terminal is a divider: drag it up or down, or focus it and use **↑**/**↓** (**Home** and **End** jump to the smallest and largest size). The terminal never shrinks below a prompt and a few lines, the editor always keeps a strip to work in, and the height you leave is remembered. Making the window shorter pulls the terminal back inside it.
- **A monospace grid with a visible cursor.** The terminal draws in the editor's font from **Settings ▸ Appearance**, follows **View ▸ Zoom**, and keeps its rows tight so a short panel still shows the prompt. A block cursor marks where typing goes. It blinks while the terminal has the keyboard and shows as an outline when another part of the window has it.
- **Click to type.** Clicking anywhere in the terminal gives it the keyboard, and it takes the keyboard when it opens or after you drag the divider.
- **Hiding no longer quits your shell.** The terminal button in the tab strip hides and shows the panel, and the shell keeps running in between: its history, its prompt and any running program are still there when you show it again. To end the shell, click **×** in the terminal's header.
- **More readable text.** Dim colors are lifted to stay readable on the terminal's background, and 24-bit colors from programs that use them are shown.

## Toolbar and window

- **Every toolbar control has a word under its icon.** When the window is too narrow for all of them, the last controls move into a **More** menu. Each row in that menu names its control and its shortcut, and shows a check mark when the control is on. **More ▸ Customize Toolbar…** opens the toolbar editor in Settings.
- **A simpler window.** The icon rail on the left, which held only the Files button, is gone. **Files** in the toolbar (and **View ▸ Files Panel**) shows and hides File View. The editor toolbar's symbols list, which only JSON ever filled, is gone too.
- **The status bar's EDIT / READ ONLY chip now shows the mode and is no longer a second switch.** Switch the mode with the editor toolbar's mode button, **View ▸ Read-Only Mode**, the command palette, or **Ctrl/⌘ Shift L**. The chip's tooltip lists them.

## Fixed

- The **More** menu opened behind the plugins panel, so its rows could not be clicked.
- The plugins panel now closes on **Escape**, like the other dialogs.
- Dragging the File View edge to a fractional width could stop the session from saving.
- In preview builds of this release, the installed terminal showed a proportional font, no cursor, and a divider that did nothing. The app's security policy blocked the styles the terminal sets while it runs. Nulis now applies those styles in a way the policy allows, and the policy itself is unchanged.

## First launch

These builds are not signed with a paid Apple or Microsoft certificate, so each system asks once.

- **macOS:** open the `.dmg` and drag Nulis into Applications, then open it. When macOS says it could not verify Nulis, click **Done**. Open **System Settings ▸ Privacy & Security**, scroll to **Security**, and click **Open Anyway** next to the message about Nulis; confirm with your password or Touch ID. You do this once per installed version.
- **Windows:** if SmartScreen shows *Windows protected your PC*, click **More info**, then **Run anyway**.
- **Linux:** no extra step; the package manager installs the libraries Nulis needs.

## Known limitations

- **The terminal is checked on macOS only.** Windows and Linux have automated checks only. The terminal's styles were checked in a browser running the app's security policy; the final check of the installed macOS app is by hand.
- **Clicking in the terminal does not move the shell's caret** to the place you clicked. Your shell (zsh, bash) draws the line you are typing, and Nulis has no shell integration to move its caret.
- **The terminal's cursor keeps blinking** when the system asks for reduced motion.
- **Application shortcuts** such as **Cmd+P** and **Cmd+W** still go to Nulis while the terminal has the keyboard, the same as in the editor.
- The terminal keeps 5,000 lines of scrollback. When very long output overflows the buffer, the terminal says `[older terminal output was discarded]` where the old lines were.
- Builds are not signed with a Developer ID or code-signing certificate, hence the first-launch steps above.
- On Windows and Linux, Nulis does not yet add itself to the system's "Open with" list.
- Linux packages are for 64-bit x86 only.
